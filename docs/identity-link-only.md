# Temporary identity authorization

The existing `POST /api/oauth/authorizations` route accepts an optional `linkOnly` object for a trusted host proving a member's identity with an already installed local OAuth app. This mode requires an administrator bearer, encrypted state, and a provider's catalog-declared `identityScopes`. It accepts no replacement client credentials or authorization options. The installed credential must affirmatively name the same client id as its sealed client configuration (or the deployment configuration when that was the installed client).

The trusted host supplies `clientFromConnection`, its logical `connectionAlias` and `connectionVersionId` receipt, the identity-only `requestedScopes`, `returnUri`, and its signed `returnState`. The destination must be on `OOMOL_CONNECT_OAUTH_RESULT_ORIGINS` with path `/links/<service>/callback`. The temporary `connectionName` starts with `link_` and differs from the installed connection. The caller remains responsible for authenticating its member and checking that receipt against its accepted binding at consent start and completion. Open Connector does not invent an account-ownership reconciliation protocol.

Consent uses the normal provider code exchange and the frozen, sealed app configuration. Success redirects with `code=<oauthAuthorizationId>` and the host's original `state`, never an access token. `GET /api/connections?service=<service>&connectionName=<alias>` returns the existing array shape with just that alias; `linkOnly` is a non-secret receipt, while client configuration remains sealed. The host invokes the catalog identity action on that alias and deletes it through ordinary `DELETE /api/connections/<service>` before completing its member link. The installed binding is never replaced.

The temporary alias is reserved atomically under the existing disconnect lock, using its ordinary `oauth_states` row. That same row retains cleanup ownership through token exchange, so concurrent authorizations cannot claim the alias in between. A temporary credential cannot supply the installed app for another link. An expiry sweep rechecks the exact selected state and retirement generation in its disconnect transaction; a stale selection does not retire a reused alias. Explicit alias deletion removes it. Abandoned pending and completed link authorizations become eligible for retirement after the existing fifteen-minute authorization lifetime. Node's existing maintenance runs at startup and every sixty seconds, and the Cloudflare scheduled entry invokes the same sweep without HTTP traffic. Each pass reads up to one hundred expired states; backlog, maintenance failure or an unavailable database can delay retirement. Retirement uses the existing disconnect fence so an in-flight callback cannot republish after expiry. This deletes local credentials; it does not claim provider-side revocation for providers that publish no revocation endpoint.

The flow and restart/retirement fixtures are authored examples, not recorded provider consent. TypeScript checking and all 220 tests across the OAuth-flow, runtime-store and server suites pass. These checks also retain ordinary popup cancellation and use one exact stored-alias lookup. Full CI and real-provider qualification remain required before release.
